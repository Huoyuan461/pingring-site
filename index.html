核 心 功 能

简单机制，完整闭环

原理只有一句话：任务完成后向讯环打一次卡；到期没等到打卡，就判定异常并发起通知。

01

心跳打卡监控

每个任务对应一个专属打卡 URL（或打卡邮箱）。支持开始/成功/失败信号，还能回传运行时长，跑太久同样告警。

02

三种调度方式

固定间隔、Cron 表达式、systemd OnCalendar 表达式，附带宽限期设置——晚几分钟不误报，超时才升级。

03

40+ 通知渠道

企业微信、钉钉、飞书深度适配（机器人 Webhook、加签/签名校验、错误感知），另有邮件、短信、电话、Webhook、Telegram、Slack 等四十余种。

04

状态页与徽章

为每个项目生成公开状态徽章，嵌到内部 Wiki 或值班大屏上，服务健康一目了然。

05

团队与项目

按项目组织检查项与渠道，成员分级授权；谁负责什么系统，告警就精准送到谁手里。

06

开放 API

完整的 REST API，可把检查项的创建、暂停、状态查询接入你现有的运维脚本与发布流程。

企业微信 钉钉 飞书 电子邮件 Webhook 短信 电话 Telegram Slack Discord PagerDuty ntfy 等 40+ 种
部 署 上 线

三步，装进你自己的服务器

一台 1 核 2G 的 Linux 服务器即可（Docker 环境）。数据全程在你的内网，不经过任何第三方。

一

运行一键安装

解压交付包，运行安装脚本：自动生成密钥、拉起数据库与 Web 服务、完成初始化。

# 在服务器上
./install.sh
二

创建检查项

登录中文界面，创建管理员账号与第一个检查项，并接好企业微信、钉钉或飞书机器人。

三

给任务加上打卡

在你的脚本或 crontab 末尾加一行 curl。任务照常跑，讯环开始站岗。

# 任务成功后打卡
curl -fsS https://ping.example.com/ping/<uuid>

常 见 问 题

先问清楚，再决定

数据会经过你们的服务器吗？

不会。讯环是私有化部署：软件装在你自己的服务器上，检查记录、账号与通知配置全部保存在本地数据库中，数据不出内网。

它能监控哪些东西？

一切“应该定期发生、但可能悄悄失败”的事情：cron 定时任务、数据备份、报表生成、ETL 同步、证书续期，以及任何能发出 HTTP 请求的服务与脚本。服务本身也可以定时调用打卡接口做存活上报。

和按月付费的云端监控服务有什么区别？

两点：一是部署位置——讯环在你的内网里，适合不能把运维数据交给外部平台的团队；二是付费方式——一次性买断，没有按量、按席位、按年续费的持续支出。

讯环的软件基础可靠吗？

讯环基于成熟的开源项目 Healthchecks 构建（BSD 3-Clause 开源许可证），在其久经验证的监控内核之上做了品牌、中文界面与国内通知渠道的适配，并按许可证要求完整保留了上游版权与许可声明。

服务器有什么要求？

一台能跑 Docker 的 Linux 服务器即可，1 核 2G 起步可支撑中小团队的监控量；数据库使用 PostgreSQL，随部署包一并安装。
